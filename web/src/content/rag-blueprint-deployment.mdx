This hands-on section deploys the NVIDIA RAG Blueprint with Helm. The lab values file keeps model inference on NVIDIA hosted endpoints and configures the vector database path for CPU operation.

## Prerequisites

`NGC_API_KEY` is required to pull the RAG Helm chart, access NGC container images, and call NVIDIA hosted endpoints.

If you do not have a key yet, follow NVIDIA's [Generating NGC API Keys](https://docs.nvidia.com/ngc/latest/ngc-user-guide.html#generating-ngc-api-keys) documentation. You can manage keys from the [NGC API Keys page](https://org.ngc.nvidia.com/account/api-keys).

```bash-ref
export NGC_API_KEY="<your-ngc-or-nvidia-api-key>"
```

<Callout type="warn" title="Keep keys private">
Do not paste real keys into shared logs or committed files. The commands below pass the key to Helm so Kubernetes secrets can be created by the chart.
</Callout>

## 1. Create the namespace

Create the namespace if it does not already exist:

```bash
kubectl create namespace rag
```

## 2. Inspect the chart defaults

Start by looking at the upstream chart defaults. This helps you see what the lab override file is changing.

```bash
helm show values https://helm.ngc.nvidia.com/nvidia/blueprint/charts/nvidia-blueprint-rag-v2.5.0.tgz \
  --username '$oauthtoken' \
  --password "$NGC_API_KEY" | sed -n '1,220p'
```


## 3. Inspect the lab values file

This repository includes the custom values used by the launchable:

```bash
cat manifests/rag-values.yaml
```

The important settings are:

- Hosted endpoints: for the RAG `v2.5.0` services, empty model server URL fields mean "use NVIDIA hosted endpoints" instead of in-cluster NIM services. The NV-Ingest runtime is stricter, so the lab sets `EMBEDDING_NIM_ENDPOINT` explicitly to the hosted embeddings base URL.
- RAG `v2.5.0` model names: the lab uses the `v2.5.0` default hosted models that are currently available: `APP_EMBEDDINGS_MODELNAME` and `EMBEDDING_NIM_MODEL_NAME` use `nvidia/llama-nemotron-embed-1b-v2`, and `APP_RANKING_MODELNAME` uses `nvidia/llama-nemotron-rerank-1b-v2`.
- Local NIM services disabled: the `nimOperator` overrides disable local model-serving pods so the lab does not require GPUs or large model caches.
- CPU vector database path: `APP_VECTORSTORE_ENABLEGPUSEARCH` and `APP_VECTORSTORE_ENABLEGPUINDEX` are set to `False`, and the Milvus image is set to the CPU image tag.
- Text-focused ingestion: table, chart, image, and infographic extraction are disabled so the launchable can focus on document text ingestion without requiring extraction NIMs.
- Smaller NV-Ingest footprint: the upstream NV-Ingest defaults request much larger resources than this launchable provides. The lab values reduce `nv-ingest.resources`, `MAX_INGEST_PROCESS_WORKERS`, `NV_INGEST_MAX_UTIL`, and `PDF_SPLIT_PAGE_COUNT` for an 8 CPU / 32 GiB VM.
- Secrets are not stored in the file. The API key is passed through Helm flags during installation.

## 4. Install the RAG Blueprint

Install the chart with the lab values file:

```bash
helm upgrade --install rag -n rag \
  https://helm.ngc.nvidia.com/nvidia/blueprint/charts/nvidia-blueprint-rag-v2.5.0.tgz \
  --username '$oauthtoken' \
  --password "$NGC_API_KEY" \
  --set imagePullSecret.password="$NGC_API_KEY" \
  --set ngcApiSecret.password="$NGC_API_KEY" \
  -f manifests/rag-values.yaml \
  --wait --timeout 20m
```

## 5. Validate the deployment

Check the pods:

```bash
kubectl get pods -n rag
```

Expected shape:

```text
rag-server-...        1/1 Running
ingestor-server-...   1/1 Running
rag-frontend-...      1/1 Running
rag-minio-...         1/1 Running
rag-redis-...         1/1 Running
```

Check the services:

```bash
kubectl get svc -n rag
```

The services AI-Q will use later are:

- `rag-server` on port `8081`
- `ingestor-server` on port `8082`
- `rag-frontend` on port `3000`, exposed through Envoy at `/rag`
- Envoy browser-facing `/api/...` paths, which forward selected RAG UI requests to the in-cluster RAG server and ingestor APIs

Verify the Envoy route:

```bash
kubectl get httproute -n rag rag-frontend
```

Open the same Brev launchable endpoint you use for AI-Q on port `3001`, then add `/rag` to the URL path. The tutorial UI remains on port `3000`; Envoy serves application frontends from port `3001`. The `/rag` path is an entry point to the RAG UI and redirects to the RAG frontend root on the same Envoy port.

The RAG frontend is a Vite app using root-level routes and assets. The lab Envoy route handles `/`, `/settings`, `/collections`, `/assets/...`, and the RAG-specific `/api/...` calls needed by the browser. Those specific `/api/...` matches are required because AI-Q also uses root-level `/api` paths on the same Envoy host.

Check rollout status for the main services:

```bash
kubectl rollout status deployment/rag-server -n rag --timeout=5m
kubectl rollout status deployment/ingestor-server -n rag --timeout=5m
kubectl rollout status deployment/rag-frontend -n rag --timeout=5m
```

## 6. Troubleshoot

If a pod is not ready, inspect events and logs:

```bash
kubectl get events -n rag --sort-by='.lastTimestamp'
```

For `Pending` pods, describe the pod and look at the scheduler message:

```bash
kubectl describe pod -n rag <pending-pod-name>
```

If you see `Insufficient cpu` or `Insufficient memory` for `rag-nv-ingest`, the chart is still using resource requests that are too large for the launchable. Confirm the rendered values:

```bash
helm get values rag -n rag --all | grep -nE "nv-ingest:|resources:|MAX_INGEST_PROCESS_WORKERS|NV_INGEST_MAX_UTIL|PDF_SPLIT_PAGE_COUNT" -A12 -B2
```

If `rag-nv-ingest` enters `CrashLoopBackOff` with an `ImageCaptionExtractionSchema` error such as `endpoint_url Input should be a valid string`, or a `TextEmbeddingSchema` error such as `embedding_nim_endpoint Input should be a valid string`, an NV-Ingest endpoint was rendered as `None`. Confirm the deployed environment:

```bash
kubectl get deploy rag-nv-ingest -n rag -o yaml | grep -nE "EMBEDDING_NIM_ENDPOINT|EMBEDDING_NIM_MODEL_NAME|VLM_CAPTION_ENDPOINT|APP_NVINGEST_CAPTIONENDPOINTURL|APP_VLM_SERVERURL" -A2 -B2
```

The lab values should set `EMBEDDING_NIM_ENDPOINT` to the base URL `https://integrate.api.nvidia.com/v1` and `VLM_CAPTION_ENDPOINT` to `https://integrate.api.nvidia.com/v1/chat/completions`.

If ingestion fails with a URL like `https://integrate.api.nvidia.com/v1/embeddings/embeddings`, the endpoint was configured with the operation path included. Use the base `/v1` URL instead.

If ingestion fails with `410 Client Error: Gone for url: https://integrate.api.nvidia.com/v1/embeddings`, the endpoint is reachable but the hosted service rejected the embedding request. First confirm that the deployed pod has the RAG `v2.5.0` model name:

```bash
kubectl get deploy rag-nv-ingest -n rag -o jsonpath='{range .spec.template.spec.containers[*].env[*]}{.name}={.value}{"\n"}{end}' | \
  grep -E "EMBEDDING_NIM_MODEL_NAME|EMBEDDING_NIM_ENDPOINT"
```

Expected values:

```text
EMBEDDING_NIM_ENDPOINT=https://integrate.api.nvidia.com/v1
EMBEDDING_NIM_MODEL_NAME=nvidia/llama-nemotron-embed-1b-v2
```

Also check the RAG server and ingestor model settings:

```bash
kubectl get deploy -n rag rag-server ingestor-server -o jsonpath='{range .items[*]}{"\n"}{.metadata.name}{"\n"}{range .spec.template.spec.containers[*].env[*]}{.name}={.value}{"\n"}{end}{end}' | \
  grep -E "rag-server|ingestor-server|APP_EMBEDDINGS_MODELNAME|APP_RANKING_MODELNAME|APP_EMBEDDINGS_SERVERURL|APP_RANKING_SERVERURL"
```

Then reapply the lab values:

```bash
helm upgrade --install rag -n rag \
  https://helm.ngc.nvidia.com/nvidia/blueprint/charts/nvidia-blueprint-rag-v2.5.0.tgz \
  --username '$oauthtoken' \
  --password "$NGC_API_KEY" \
  --set imagePullSecret.password="$NGC_API_KEY" \
  --set ngcApiSecret.password="$NGC_API_KEY" \
  -f manifests/rag-values.yaml \
  --wait --timeout 20m
```

```bash
kubectl logs -n rag deploy/rag-server --since=10m
```

You can also run direct health checks from inside the cluster. 

Start a temporary curl pod to check the RAG server:

```bash
kubectl run rag-healthcheck -n rag --rm -i --restart=Never \
  --image=curlimages/curl:8.10.1 -- \
  curl -sf http://rag-server:8081/health
```

Then check the ingestor server:

```bash
kubectl run rag-ingestor-healthcheck -n rag --rm -i --restart=Never \
  --image=curlimages/curl:8.10.1 -- \
  curl -sf http://ingestor-server:8082/health
```

Expected result: each endpoint returns HTTP `200` or a successful health response.
