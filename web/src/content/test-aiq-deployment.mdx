At this point the cluster has the AI-Q release installed. This section helps you build confidence that each service is healthy, that the UI is reachable through the launchable endpoint, and that AI-Q can route different types of requests through different agent paths.

## 1. Verify the installation

```bash
kubectl get pods -n ns-aiq
```

Expected shape:

```text
aiq-backend-...    1/1 Running
aiq-frontend-...   1/1 Running
aiq-postgres-...   1/1 Running
```

The default deployment includes these main pods:

- `aiq-backend`: runs the AI-Q API and agent workflow. This is where request routing, model calls, tool execution, and research orchestration happen.
- `aiq-frontend`: serves the web UI that you use to submit prompts and inspect responses.
- `aiq-postgres`: stores backend state used by the AI-Q services, including job and checkpoint data configured by the deployment.

Verify the k8s services:

```bash
kubectl get svc -n ns-aiq
```

Verify the Gateway and HttpRoute used to expose the frontend service:

```bash
kubectl get gateway -n aiq-gateway
```
```bash
kubectl get httproute -n ns-aiq aiq-frontend
```

## 2. Test the backend health check

Run the health check from inside the cluster with a temporary curl pod. This avoids using `kubectl port-forward`, which would block the embedded terminal.

```bash
kubectl run aiq-backend-healthcheck -n ns-aiq --rm -i --restart=Never \
  --image=curlimages/curl:8.10.1 -- \
  curl -sf http://aiq-backend:8000/health | jq
```

Expected result: the command exits successfully and prints the backend health response.

```
{
  "status": "healthy"
}
```

## 3. Access the AI-Q web UI

The tutorial UI itself runs on port `3000`, so AI-Q needs a different external entry point. This launchable exposes AI-Q through Envoy Gateway on host port `3001` at the `/aiq` path.

The button opens the Brev exposed-port link for Envoy with the `/aiq` path. In Brev, each exposed port can have its own tunnel hostname, so the correct URL usually looks like a separate secure tunnel ending in `/aiq`, without an explicit `:3001` suffix.

## Route test overview

Use the next four prompts to watch AI-Q choose different paths through the architecture:

| Route | Prompt shape | Expected behavior | Useful log keywords |
|---|---|---|---|
| Meta response | Ask what AI-Q can do | Direct capability-style answer without research tools | `intent_classifier`, `meta`, `workflow` |
| Shallow research | Ask for a specific current fact or short summary | Fast answer with web search/tool activity and citations | `shallow_research_agent`, `web_search_tool`, `tavily`, `citation` |
| Deep research | Ask for comparison, tradeoffs, and recommendation | Planned, multi-step research with a more report-like answer | `deep_research_agent`, `planner`, `researcher`, `writer`, `report` |
| Escalation or clarification | Ask a broad strategic question | Routing decision may move from a lighter path to clarification or deeper research | `escalation`, `clarifier_agent`, `route`, `decision` |


## 4. Test a meta-response route

Start with a prompt that asks about AI-Q itself. This is a good first test because it should stay on the meta-response path: the system can answer from its own capabilities without using web search or deeper research planning.

In the AI-Q UI, open a new chat and send:

```text
What can you help me with?
```

You should receive a capabilities-style response rather than a long research report.

```bash
kubectl logs -n ns-aiq deploy/aiq-backend --since=5m | grep -Ei "intent|meta|classifier|workflow|agent"
```

Look for keywords such as `intent_classifier`, `meta`, `user_intent`, or `workflow`. The exact log wording can vary by image version and log level, but this request should not look like a web-search-heavy or deep-research run.



## 5. Test a shallow research route

Next, test a prompt that needs current outside information but does not require a long research plan. A good shallow research candidate is specific, factual, and answerable with a small number of web search calls.

In the AI-Q UI, send:

```text
What are the latest NVIDIA AI Enterprise release highlights?
```

This should route differently from the meta-response prompt. AI-Q should classify the request as research, use the shallow researcher, call web search tools, and return a concise answer with sources instead of a multi-section report.

Check the backend logs again:

```bash
kubectl logs -n ns-aiq deploy/aiq-backend --since=5m | grep -Ei "shallow|research|web_search|tavily|tool|citation|intent"
```

Look for keywords such as `shallow_research_agent`, `web_search_tool`, `tavily`, `tool`, `citation`, or `research`. Compared with the meta-response test, this log output should show tool or search activity and shallow research routing.

If the response looks like a deep report or asks for clarification, try a narrower factual query. If the response has no sources, confirm `TAVILY_API_KEY` was set before the Helm install and that the `aiq-credentials` secret exists in `ns-aiq`.

## 6. Test a deep research route

Now test a prompt that should require planning, multiple search/retrieval passes, synthesis, and a more structured answer. A good deep research candidate asks for comparison, tradeoffs, and a recommendation rather than a single factual lookup.

In the AI-Q UI, send:

```text
Compare Kubernetes deployment patterns for enterprise RAG systems, including managed Kubernetes, self-managed clusters, and hybrid deployments. Recommend one approach for a regulated financial services team and explain the tradeoffs.
```

This should route differently from shallow research because the question asks for a multi-part analysis and a recommendation. AI-Q should need to break the task down, gather evidence from multiple sources, reason across criteria, and produce a more report-like answer.

Check the backend logs:

```bash
kubectl logs -n ns-aiq deploy/aiq-backend --since=10m | grep -Ei "deep|planner|researcher|writer|plan|section|citation|report|async|checkpoint|intent"
```

Look for keywords such as `deep_research_agent`, `planner`, `researcher`, `writer`, `plan`, `report`, `checkpoint`, `citation`, or `async`. Compared with the shallow route, this output should show more planning and synthesis activity, not just one or two tool calls.

If the response is short and shallow, make the request more explicitly comparative. Words like `compare`, `evaluate`, `recommend`, `tradeoffs`, and `for a regulated team` help signal that the answer needs deeper research.

## 7. Test an escalation route

Finally, test a prompt that starts small but naturally requires deeper analysis. Escalation is useful when AI-Q begins in a lighter route and decides the request needs a stronger research path to answer well.

In the AI-Q UI, send:

```text
Should our platform team standardize on one retrieval architecture for all business units, or allow teams to choose their own RAG stack? Consider cost, governance, operational complexity, and time to production.
```

This is a good escalation candidate because it is framed as a strategic decision. It is broader than a shallow fact lookup, but it is not simply asking for a generic deep report from the first word. AI-Q may classify the request, discover that a useful answer needs structured evaluation, and escalate toward deeper research or clarification.

Check the backend logs:

```bash
kubectl logs -n ns-aiq deploy/aiq-backend --since=10m | grep -Ei "escalat|clarif|deep|shallow|intent|route|decision|workflow|research"
```

Look for keywords such as `escalation`, `enable_escalation`, `clarifier_agent`, `deep_research_agent`, `shallow_research_agent`, `route`, `decision`, or `intent_classifier`. The exact wording depends on the image and log level, but this test should show routing decisions and may show the workflow moving from an initial route toward a deeper one.

If AI-Q asks a clarifying question, that is also a valid signal. The clarifier route can appear when the system decides the request is too broad or under-specified to answer responsibly. Answer the clarification and continue; the next turn should give you a better signal about whether AI-Q continues with shallow or deep research.
