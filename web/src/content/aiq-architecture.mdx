AI-Q is organized around an orchestration graph that decides how much research a request needs before spending time and model calls. The architecture is intentionally split into a fast path for simple work and a deeper path for more complex research.

## Core components

| Component | Role in the architecture |
| --- | --- |
| Intent Classifier | Classifies the request, generates direct meta responses when appropriate, and chooses shallow or deep research for research requests. |
| Clarifier Agent | Adds a human-in-the-loop checkpoint before deep research by asking focused questions and producing a structured research plan for approval. |
| Shallow Researcher | Performs fast, bounded research with tools, citations, and a final synthesis for simpler questions. |
| Deep Researcher | Coordinates a multi-phase research workflow for comprehensive answers, including planning, source gathering, drafting, and citation validation. |
| Chat Researcher Orchestrator | Maintains the LangGraph state machine that connects routing, research, clarification, and final response generation. |

## Agent roles

### Intent Classifier

The Intent Classifier is the entry point for every query. It combines three decisions in one model call: whether the request is meta or research-oriented, whether a direct answer is enough, and whether a research request should use the shallow or deep path.

The classifier keeps the system efficient. A simple system question does not need a research workflow, while a broad investigation should not be forced through a quick lookup path.

### Clarifier Agent

The Clarifier Agent runs before deep research when human review is enabled. It can ask clarification questions, create a structured plan with sections and research goals, and wait for user approval before the deeper workflow starts.

This step is useful when the request is open-ended, risky to interpret too narrowly, or likely to benefit from explicit scope before the agents spend time gathering sources.

### Shallow Researcher

The Shallow Researcher is optimized for speed. It uses tool calls within a configured budget, rewrites queries when useful, compacts context, verifies citations, and produces a concise answer when the budget is reached.

### Deep Researcher

The Deep Researcher is optimized for thoroughness. It uses an orchestrator with specialized planning and research subagents to build evidence-grounded outlines, execute searches, synthesize findings, and produce a more complete report.

This path is where AI-Q spends more effort on planning, iterative evidence gathering, citation checks, and final synthesis.

## Request flow

Every request starts at the Intent Classifier. From there, AI-Q can answer directly, run shallow research, or move into a deeper workflow with clarification and planning. Use the examples below to see how different requests move through the system.

The shallow path can also escalate to deeper research when the initial result suggests that the query needs more planning, broader analysis, or user-approved scope.

## State and control

The orchestrator carries shared state through the graph: the message history, user information, selected data sources, the intent decision, the depth decision, shallow research output, clarifier output, and final report. This gives AI-Q a consistent way to route requests while still allowing individual agents to specialize.
