This hands-on section deploys AI-Q from the NGC Helm chart package.

## Prerequisites

Before running the deployment commands, make sure these values are available in the lab shell:

`NGC_API_KEY` is used to authenticate to NGC and NVIDIA hosted model endpoints.

If you do not have a key yet, follow NVIDIA's [Generating NGC API Keys](https://docs.nvidia.com/ngc/latest/ngc-user-guide.html#generating-ngc-api-keys) documentation. You can manage keys from the [NGC API Keys page](https://org.ngc.nvidia.com/account/api-keys); for this lab, the key needs access to NGC Catalog artifacts and NVIDIA hosted API endpoints.

```bash-ref
export NGC_API_KEY="<your-ngc-or-nvidia-api-key>"
```

`TAVILY_API_KEY` enables web search for AI-Q research workflows.

If you do not have a Tavily key yet, follow the [Tavily Quickstart](https://docs.tavily.com/documentation/quickstart) or the Tavily help article on [creating an API key](https://help.tavily.com/articles/9170796666-how-can-i-create-an-api-key). The key is copied from your Tavily Platform dashboard.

```bash-ref
export TAVILY_API_KEY="<your-tavily-api-key>"
```



<Callout type="warn" title="Keep keys private">
Do not paste real keys into shared logs or committed files. The commands below read keys from environment variables and store them in Kubernetes secrets.
</Callout>

## 1. Create the namespace

```bash
kubectl create namespace ns-aiq --dry-run=client -o yaml | kubectl apply -f -
```

## 2. Create application secrets

The AI-Q Helm docs require a Kubernetes secret named `aiq-credentials`. This lab stores API keys in that secret and keeps database credentials at the tutorial defaults.

```bash
kubectl create secret generic aiq-credentials -n ns-aiq \
  --from-literal=NVIDIA_API_KEY="$NGC_API_KEY" \
  --from-literal=TAVILY_API_KEY="$TAVILY_API_KEY" \
  --from-literal=DB_USER_NAME="aiq" \
  --from-literal=DB_USER_PASSWORD="aiq_dev" \
  --dry-run=client -o yaml | kubectl apply -f -
```

```bash
kubectl get secret aiq-credentials -n ns-aiq
```

Create the NGC image pull secret:

```bash
kubectl create secret docker-registry ngc-secret -n ns-aiq \
  --docker-server=nvcr.io \
  --docker-username='$oauthtoken' \
  --docker-password="$NGC_API_KEY" \
  --dry-run=client -o yaml | kubectl apply -f -
```

```bash
kubectl get secret ngc-secret -n ns-aiq
```

## 3. Pull the AI-Q Helm chart

Pull the chart archive using your NGC API key:

```bash
helm pull https://helm.ngc.nvidia.com/nvidia/blueprint/charts/aiq2-web-2.0.0.tgz \
  --username '$oauthtoken' \
  --password "$NGC_API_KEY"
```

Confirm the archive exists:

```bash
ls -lh aiq2-web-2.0.0.tgz
```

## 4. Inspect the custom values file

The provided `manifests/aiq-values.yaml` is the values file you will pass to Helm for this deployment.

```bash
cat manifests/aiq-values.yaml
```

The file contains the launchable-specific overrides used by this tutorial, including image pull secret configuration for the AI-Q application components. 

You can still inspect the chart defaults for comparison:

```bash
helm show values aiq2-web-2.0.0.tgz | sed -n '1,220p'
```

The Helm chart tells the backend which config file to load, but the config file itself is not stored as a standalone file in the chart archive. 

`CONFIG_FILE` is resolved inside the running backend container. A value such as `configs/config_web_default_llamaindex.yml` points to a file packaged in the backend image, not to GitHub and not to your local laptop filesystem.

The source repository publishes the packaged config examples under [configs/](https://github.com/NVIDIA-AI-Blueprints/aiq/tree/develop/configs), which is useful for reading and comparing the content of files already packaged in the backend image.



Start by inspecting the backend environment values from the chart defaults. The backend loads its AI-Q workflow configuration from the `CONFIG_FILE` environment variable:

```bash
helm show values aiq2-web-2.0.0.tgz | grep -B4 "CONFIG_FILE"
```

You should see the default non-FRAG web config:

```yaml
aiq:
  apps:
    backend:
      env:
        CONFIG_FILE: configs/config_web_default_llamaindex.yml
```


To use a local custom config, you must first mount that file into the backend pod, then set `CONFIG_FILE` to the mounted path. `Part IV` shows that pattern with a Kubernetes ConfigMap and Helm values. 
When you adapt the lab later you will change the default `CONFIG_FILE` to integrate the Foundational RAG as a data source.


## 6. Install AI-Q Helm Chart

Install the release with the provided values file:

```bash
helm upgrade --install aiq ./aiq2-web-2.0.0.tgz \
  -n ns-aiq \
  --wait --timeout 10m \
  -f manifests/aiq-values.yaml
```

After AI-Q is installed, confirm which `CONFIG_FILE` value the backend received from the rendered Deployment:

```bash
kubectl get deploy aiq-backend -n ns-aiq \
  -o jsonpath='{.spec.template.spec.containers[?(@.name=="backend")].env[?(@.name=="CONFIG_FILE")].value}{"\n"}'
```


## 7. Troubleshoot

If the install fails, start with events and pod logs:

```bash
kubectl get events -n ns-aiq --sort-by='.lastTimestamp'
```

```bash
kubectl get pods -n ns-aiq
```

- You inspected the lab values file and the chart defaults, including the packaged `CONFIG_FILE` setting.
- You installed AI-Q with Helm using the launchable-specific values.
- You confirmed the backend deployment received the expected config file reference.
