After the RAG Blueprint is running, upgrade AI-Q so its backend can use FRAG as a knowledge source. FRAG gives AI-Q access to the RAG server and ingestor APIs that were deployed in the previous section.

## 1. Inspect the FRAG values file

This repository includes a small AI-Q override file for FRAG integration:

```bash
cat manifests/aiq-frag-values.yaml
```

The key settings are:

- `CONFIG_FILE: configs/config_web_frag.yml` selects the AI-Q backend workflow that knows how to use FRAG.
- `RAG_SERVER_URL` points AI-Q to the RAG query service inside the cluster.
- `RAG_INGEST_URL` points AI-Q to the RAG ingestion service inside the cluster.
- `COLLECTION_NAME` tells AI-Q which RAG collection to query when it uses the Knowledge Base data source.

## 2. Confirm RAG service DNS

AI-Q will call RAG through Kubernetes service DNS. Confirm the services exist:

```bash
kubectl get svc -n rag rag-server ingestor-server
```

The expected in-cluster URLs are:

```text
http://rag-server.rag.svc.cluster.local:8081/v1
http://ingestor-server.rag.svc.cluster.local:8082
```

## 3. Upgrade AI-Q

Upgrade AI-Q with both the base lab values and the FRAG override file:

```bash
helm upgrade --install aiq ./aiq2-web-2.0.0.tgz \
  -n ns-aiq \
  --wait --timeout 10m \
  -f manifests/aiq-values.yaml \
  -f manifests/aiq-frag-values.yaml
```

Verify the backend rolls out:

```bash
kubectl rollout status deployment/aiq-backend -n ns-aiq --timeout=5m
```

Confirm the backend received the FRAG environment variables:

```bash
kubectl get deploy aiq-backend -n ns-aiq \
  -o jsonpath='CONFIG_FILE={.spec.template.spec.containers[?(@.name=="backend")].env[?(@.name=="CONFIG_FILE")].value}{"\n"}RAG_SERVER_URL={.spec.template.spec.containers[?(@.name=="backend")].env[?(@.name=="RAG_SERVER_URL")].value}{"\n"}RAG_INGEST_URL={.spec.template.spec.containers[?(@.name=="backend")].env[?(@.name=="RAG_INGEST_URL")].value}{"\n"}COLLECTION_NAME={.spec.template.spec.containers[?(@.name=="backend")].env[?(@.name=="COLLECTION_NAME")].value}{"\n"}'
```

Expected values:

```text
CONFIG_FILE=configs/config_web_frag.yml
RAG_SERVER_URL=http://rag-server.rag.svc.cluster.local:8081/v1
RAG_INGEST_URL=http://ingestor-server.rag.svc.cluster.local:8082
COLLECTION_NAME=default
```

## 4. Inspect the RAG collections

AI-Q uses `RAG_INGEST_URL` for file and collection operations. When you upload a file from the AI-Q UI **Files** tab, the AI-Q backend sends that upload to the RAG ingestor service at `RAG_INGEST_URL`.

In this lab, `RAG_INGEST_URL` points to:

```text
http://ingestor-server.rag.svc.cluster.local:8082
```

Before uploading a file, inspect the collections currently known by the RAG ingestor:

```bash
kubectl run rag-collections-check -n rag --rm -i --restart=Never \
  --image=curlimages/curl:8.10.1 -- \
  sh -c 'curl -sS -w "\nHTTP %{http_code}\n" http://ingestor-server:8082/collections'
```

The collection queried by AI-Q is controlled by `COLLECTION_NAME`. This lab uses `default`:

```text
COLLECTION_NAME=default
```

If you want AI-Q to query a different populated collection, update `COLLECTION_NAME` in `manifests/aiq-frag-values.yaml` and upgrade AI-Q again.

## 5. Test FRAG from the AI-Q UI

Return to the AI-Q UI at the Brev endpoint for port `3001` with the `/aiq` path.

<AppLaunchButton label="Open AI-Q UI" path="/aiq" port={3001} />

Follow this sequence:

1. Open **Data Sources**.
2. In **Connections**, disable **Web Search**.
3. Open the **Files** tab.
4. Upload a PDF or text document from the AI-Q UI.
5. Wait until ingestion finishes.
6. Ask a question that can only be answered from the uploaded file.

Example:

```text
Using the uploaded document, summarize the main problem, the proposed solution, and any implementation constraints.
```

This is a good FRAG test because AI-Q should need the document corpus rather than a general web answer. While the model is thinking, the selected data source should mention the uploaded file name or file-backed knowledge source instead of only **Web Search**.

After upload, inspect the collections again. You should see the collection used by AI-Q and the uploaded file counted in its metadata:

```bash
kubectl run rag-collections-after-upload -n rag --rm -i --restart=Never \
  --image=curlimages/curl:8.10.1 -- \
  sh -c 'curl -sS -w "\nHTTP %{http_code}\n" http://ingestor-server:8082/collections'
```

Use the collection metadata from `/collections` as the primary verification signal. A successful upload should increase `number_of_files`, `total_elements`, or `num_entities` for the collection that AI-Q is configured to query.

Check AI-Q backend logs:

```bash
kubectl logs -n ns-aiq deploy/aiq-backend --since=10m | grep -Ei "frag|rag|knowledge|retriev|ingest|config_web_frag"
```

Check RAG server logs:

```bash
kubectl logs -n rag deploy/rag-server --since=10m | grep -Ei "generate|retriev|collection|query|citation"
```

If AI-Q does not appear to call RAG, re-check `CONFIG_FILE`, `RAG_SERVER_URL`, and `RAG_INGEST_URL` in the backend pod. If RAG receives the request but returns no useful context, confirm the document upload finished and that you are asking about content present in that document.

## 6. What just happened

- You upgraded AI-Q from the default LlamaIndex-style config to the FRAG-aware config.
- You connected AI-Q to the RAG server for retrieval and grounded generation.
- You connected AI-Q to the RAG ingestor for file uploads and collection operations.
- You verified the collection that AI-Q queries.
- You tested document-grounded answering from the AI-Q UI using the Files tab.
