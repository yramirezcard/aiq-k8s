The RAG Blueprint is split into services that handle ingestion, retrieval, generation, storage, and user interaction. That separation matters because each part of the pipeline can be scaled, tuned, or replaced independently.

## Core components

| Component | Function |
| --- | --- |
| RAG frontend | Web UI for uploads, chat, document interaction, and endpoint configuration. |
| RAG server | Main query API. It receives questions, retrieves context, optionally reranks results, and calls the generation model. |
| Ingestor server | Document ingestion API. It coordinates extraction, chunking, metadata, embeddings, and writes to the vector database. |
| NV-Ingest pipeline | Processes files into structured content, including text and optional multimodal extraction paths. |
| Vector database | Stores document embeddings and metadata for similarity search. This lab configures the vector database for CPU mode. |
| Object storage | Stores document artifacts and extracted content used by the ingestion and retrieval services. |
| Redis | Tracks ingestion and summary status for asynchronous operations. |
| Hosted NVIDIA endpoints | Provide model inference for generation, embeddings, reranking, and optional extraction instead of running local NIM pods. |

## How AI-Q uses this architecture

For FRAG integration, AI-Q does not need to know the internal details of document extraction or vector indexing. It only needs reachable RAG API endpoints:

- `RAG_SERVER_URL` for retrieval and grounded generation.
- `RAG_INGEST_URL` for document ingestion and corpus management.

That boundary is useful in production. The RAG team can tune ingestion, vector database settings, reranking, and document processing while AI-Q continues to use a stable service interface.

## Lab design choices

The upstream RAG Blueprint supports self-hosted model services, which can require GPU resources and large model caches. This launchable keeps the lab lightweight by using NVIDIA hosted endpoints for model inference and a CPU vector database configuration for retrieval storage.

That means the Kubernetes cluster runs the RAG application services, ingestor, frontend, storage, and vector database, while generation, embeddings, reranking, and related model calls go to NVIDIA hosted endpoints.
